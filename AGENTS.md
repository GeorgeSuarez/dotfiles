# AGENTS.md

macOS dotfiles managed with [chezmoi](https://chezmoi.io). Tooling comes from the `Brewfile`; there is no build step for the dotfiles themselves (exception: `home/dot_pi/` is a Bun workspace with `bun test` and `typecheck` scripts).

## Layout — managed files live in `home/`

```
<repo>/                  # git root; can be cloned anywhere
├── home/                # ← chezmoi sourceDir (all managed files)
│   ├── .chezmoiignore   # state-only patterns (no repo files in here)
│   ├── dot_zshrc, dot_tmux.conf, dot_gitconfig  # only top-level dotfiles
│   ├── dot_config/… (nvim, opencode, ghostty, herdr, starship)
│   ├── dot_agents/      # → ~/.agents
│   └── dot_pi/          # → ~/.pi (Pi agent harness, not a Raspberry Pi)
├── Brewfile, install.sh, README.md, AGENTS.md  # scaffolding, never applied
└── .gitignore, .git
```

- Repo root = parent of `chezmoi source-path` (`dotrepo` alias cds there). `chezmoi cd` lands in `home/`, not the repo root.
- Only `.zshrc`, `.tmux.conf`, `.gitconfig` are managed at top level — `~/.zshenv`/`~/.zprofile` are machine-generated (cargo, Docker) and intentionally unmanaged.
- `~/.config/chezmoi/chezmoi.toml` is live-generated by `install.sh` (sets `sourceDir` to this clone's `home/`) and never committed.

## Chezmoi naming (files here are NOT named like the files they manage)

- `home/dot_*` → `~/.` (e.g. `home/dot_zshrc` → `~/.zshrc`); `home/dot_config/` → `~/.config/`
- `private_*` → same name with `0600` (e.g. `home/dot_pi/agent/private_auth.json` → `~/.pi/agent/auth.json`)
- `executable_*` → same name with `+x` (e.g. `home/dot_agents/.../executable_install.mjs` → `~/.agents/.../install.mjs`)
- `~/.agents/` is global agent skills (plus managed `.skill-lock.json`); `~/.pi/agent/` is pi-specific (extensions, settings, prompts). Do not confuse them. `~/.pi/agent/skills/` is live-only (currently empty, unmanaged) — never `chezmoi add` it.
- Config lives at `~/.config/chezmoi/chezmoi.toml`, generated by `install.sh` (untracked — clone location varies). Templates (`.tmpl`) are allowed only with matching `[data]` in that file — keep 95% of files plain.

## Sync workflow — the repo and live config both change

- `~/.zshrc` defines: `dotrepo` (cd to repo root), `dotdiff` (`chezmoi status` + `chezmoi diff`), `sync-dotfiles` (review `diff`, then `apply`), `push-dotfiles` (from repo root: `git status`, `git add -u`, review `git diff --cached`, `git commit`, `git push`)
- Review-first, never blind `chezmoi re-add`: run `chezmoi diff`, then `chezmoi re-add <file>` only for files you intend to keep, then `chezmoi apply`
- Two directions: editing a repo file must be followed by `chezmoi apply` to reach the live config; editing a live config (e.g. `nvim` settings) is pulled back with `chezmoi re-add <file>`
- `~/.zshrc.local` is machine-local, never synced (sourced from `~/.zshrc`); keep it out of the repo
- Commits use conventional style: `feat(pi):`, `chore(nvim):`, `chore(ghostty):`

## Gotchas

- Secrets (`home/dot_pi/agent/private_auth.json` → `~/.pi/agent/auth.json`, `private_models-store.json` → `models-store.json`) are gitignored but applied by chezmoi. Never `git add -f` them; `push-dotfiles` uses `git add -u` (tracked-only) for this reason.
- Scaffolding (`README.md`, `AGENTS.md`, `Brewfile`, `install.sh`) lives outside `home/` so chezmoi never sees it — no ignore entries needed. `home/.chezmoiignore` covers build/VCS noise (`**/node_modules/**`, `**/.git/**`, `**/.DS_Store`) plus live state (`*.log`, `*.bak`, `**/sessions/**`, `**/mcp-cache.json`, `**/mcp-onboarding.json`); add new dependencies to `Brewfile`, not install.sh
- Never `chezmoi add`: `~/.pi/agent/sessions/**`, `mcp-cache.json`, `mcp-onboarding.json`, `*.bak`, `~/.pi/agent/skills/**` (live-only), `~/.config/opencode/{service.json,cli.json,tui.jsonc,herdr-tui-session.js}` (one holds a password), `~/.config/herdr/{*.log,plugins/,session.json,session-history.json,release-notes.json,.plugins.lock,*.sock}`
- `home/dot_config/opencode/` is the live opencode config (`opencode.jsonc`, `tui.json`, plugins, `package.json`); edits need `chezmoi apply` plus a restart to take effect. `herdr-agent-state.js` is managed by herdr (overwritten on reinstall) — `re-add` it, don't hand-edit.
- Neovim changes: read `home/dot_config/nvim/AGENTS.md` first — the config follows its own conventions (stylua, lazy.nvim)
